# 独显性能修正与候选版本验收

作者 Asryto。**记录采集时为本地 0.5.0 / World 0.4.0 候选版，尚未提交发布。** 用户指出独显性能不合格后停止发布流程，先排查和提交可核对的结果。

机器：Ryzen 7 7735H、约 16 GB RAM、AMD Radeon(TM) Graphics、RTX 4050 Laptop 6 GB；NVIDIA 驱动 581.08。原始实测摘要见 [check.json](check.json)。相同文本、固定参考特征、种子、Q8 模型和 24 kHz PCM。

## 原因与对照

固定源码中的 ggml Vulkan 分配器在非 UMA 设备上优先选择设备本地、CPU 可映射的显存。本机这条路径显著拖慢 Talker/CodePredictor 阶段。关闭可映射显存优先路径后有明显改善；对照证明分配路径的影响，**尚未确定其具体驱动/硬件内部机制**。

在同一试验 DLL、同一 NVIDIA GPU 上，仅改变 `GGML_VK_DISABLE_HOST_VISIBLE_VIDMEM`，按 A/B/A 顺序测试：

| 路径 | 合成耗时 | 首次设备回调 | RTF | 断流 |
| --- | ---: | ---: | ---: | ---: |
| A：原可映射显存路径，暖缓存 | 19.904 s | 19.921 s | 2.860 | 0 ms（整句缓冲） |
| B：设备本地显存，暖缓存 | 2.743 s | 0.508 s | 0.394 | 0 ms（流式） |
| A：恢复旧路径，暖缓存 | 20.012 s | 20.024 s | 2.875 | 0 ms（整句缓冲） |

三次 WAV 的 SHA256 都是 `9d04bd922fa110162a2f24bdb754b0bf80b405d4de27a6aa8e665c3128df7681`。因此提速没有改动同一设备上的声音波形；缓冲后的无断流不能把旧路径认定为低延迟合格。

## 可分发通用包

使用通用 CPU DLL、嵌入式 Python 3.12.10 和包内代码运行，NVIDIA 策略自动生效，无需用户手工设置环境变量。GPU 驱动缓存已经在前面的试验中暖过，以下不是首次安装驱动后的编译时间：

| 设备 | 合成耗时 | 首次设备回调 | RTF | 断流 |
| --- | ---: | ---: | ---: | ---: |
| RTX 4050，自动设备本地显存 | 2.217 s | 0.421 s | 0.319 | 0 ms |
| AMD 核显，暖缓存 | 5.670 s | 1.678 s | 0.796 | 0 ms |

最终包复测：NVIDIA 合成 2.254 s，首次设备回调 0.421 s，RTF 0.324，断流 0 ms，WAV SHA256 与前述 NVIDIA 对照一致。

AMD 在本轮首次运行的完整记录也保留：合成 10.873 s，首次设备回调 6.991 s，RTF 1.527；不能只展示最好的一次。各自 GPU 上的 WAV 与先前试验相同；不同 GPU 间的输出长度/波形不同，不能声称跨 GPU 逐字节一致。未重新取得真人听感确认。

## 设备切换、休眠、更新与诊断

- 真实 World 类和语音 worker 执行 NVIDIA → AMD → NVIDIA。先确认旧 worker 退出，再启动新进程；核显保留默认分配，独显采用设备本地显存。未改桌宠本体。
- 独显休眠/唤醒保留同一个 worker，唤醒后仍使用设备本地显存。结束后 worker 为 null，错误栏清空。
- 独立便携文件副本上实测代码更新、嵌入式 Python doctor、World 文件更新和失败回滚。模型/原生 DLL 没有复制替换，用户设置保留；World 代码需要桌宠进程重启。
- 80 项 Python 测试、40 项 Node 测试通过。浏览器面板模拟测试覆盖设备选项、更新状态、详情保留与窄屏；模拟面板不是硬件性能验收。
- 独立诊断包可用已有 Python 运行，不需要加载模型。报告保留数值与阶段，忽略聊天、配置中的账号字段和原始日志正文。没有 GitHub 凭据或没有请求提交时生成包含分析、Issue 草稿和日志的交回 ZIP。

## 边界

这些结果限于本机，后台 GPU 负载没有严格固定。首次驱动着色器编译耗时、其他显卡及实际游戏高负载仍需各自验收。Intel UHD 的原始反馈没有在 Intel 实机重新测试；缓冲修复连续性并不证明其推理已经变快。发布前应向用户报告这些限制。
