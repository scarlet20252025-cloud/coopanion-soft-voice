## 已交付

- 扩展内一键部署：魔搭优先、GitHub 备用、离线 ZIP、下载/校验/解压进度；已有部署明确显示“已部署”，失败后提示手动指南。
- 用户主动更新，自动完成校验、备份与安装；需要重启时等用户确认。自动检查只提示，不擅自安装。
- GPU 选择保存及反馈、低功耗模式、独立气泡同步、固定音色校验、日志诊断与用户授权报障。
- RTX 4050 的约 1 GiB 专用显存已有历史实测；Intel UHD 性能不能套用该结果。
- Issue #13 定位到音频码预测阶段约占 57%；完成两种 Vulkan 路径探索，均未采用。
- 双击测试工具复用安装运行时，自动识别 Intel 核显，生成四组对照和脱敏 ZIP；同时提供 AI agent / DSH 无交互入口。
- 无核显机器可完成部署：安装器列出全部显卡并要求选择，非交互运行给出可复制的 `-DeviceName` 命令；一键部署区分"没有核显"与"多个核显"，并说明选好设备后再点一次即可继续。
- 反馈分析：GTX 1660 报告中的 19.4 秒首段耗时定位为一次性着色器编译，稳态健康；见 [反馈分析](REPORT_GTX1660_20261016.md)。

## 本轮验收

工具测试覆盖自动发现当前安装、唯一 Intel 的选择逻辑、拒绝独显回退、多核显歧义、隔离配置、报告排除音频/配置及日志脱敏。通过随包 Python 在本机 AMD 核显运行完整四组真实合成，输出报告 ZIP；没有 Intel 时失败提示及打包也已验证。

设备与安装路径：6 项 Python 单元测试与 3 项 Node 测试覆盖自动选择、纯独显、多核显与无显卡四种情形；在真实便携包上验证"唯一核显自动继续"，并用纯独显夹具验证非交互报错与交互选择两条分支。

这只证明上述流程与本机合成通过：**没有 Intel UHD 或 GTX 1660 实机验收，没有设备播放或真人听感验收，不宣称新的提速或内存下降。** 证据见 `evidence/2026-10-15-intel-issue13/`，细节见 [调查报告](INTEL_UHD_ISSUE13.md)、[工具说明](INTEL_DIAGNOSTIC_KIT.md) 和 [GTX 1660 反馈分析](REPORT_GTX1660_20261016.md)。

0.5.5 / World 0.4.9 的代码修复（PR #16）已通过 6 项 Python 与 67 项 Node 测试，并在真实便携包上验证了安装器两条选择分支。**完整安装包、代码更新清单与 npm 发布尚未执行**：验收需要至少 3 GiB 可用内存做真实合成，本机当时不足；应用内一键部署的固定运行时也要在同一步对齐到 0.5.5。

## 接下来

1. 将诊断工具发给 Issue #13 的 Intel UHD 用户，收集 ZIP、电源模式及并发游戏/录屏情况。
2. 对照同设备两次基线、阶段耗时和 PCM；先排除负载波动，再决定后续原生计算/调度优化。
3. 有收益的候选仍须通过真实首声、连续播放、长句、取消、休眠恢复及音色验收，并保留 NVIDIA 回归。
4. 仅在实测启动峰值确实下降后调整对应设备的内存门槛。目前核显仍 3 / 3.5 GiB；已验证 NVIDIA 布局 2.75 / 3.25 GiB。
5. 请 GTX 1660 报告用户在**重启电脑后**朗读第一句，确认着色器磁盘缓存是否跨重启生效；只有在每次重启都慢的情况下才需要做加载期预热。
