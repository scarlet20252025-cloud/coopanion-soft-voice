# 反馈分析：GTX 1660 纯独显机器（2026-10-16）

作者 **Asryto**。来源：用户完整报告包（`coopanion-voice-report-20261016.zip`）与自动提交的 [Issue #15](https://github.com/scarlet20252025-cloud/coopanion-soft-voice/issues/15)。机器为 Intel Core i5-9400F（**无核显**）+ NVIDIA GeForce GTX 1660 4 GiB，Windows 10 19045，装的是语音引擎 0.5.3 / World 0.4.8。

## 一、真正的故障：纯独显机器无法完成部署

报告里的"问题 A"和"问题 B"是同一个根因的两种入口。

应用内一键部署走到设备选择时，代码要求"恰好一块核显"，否则进入 `choose_device` 并 **return**——此时 `runtime-profile.json` 还没写入。World 的 `profile()` 读不到该文件，于是所有面板调用都失败。用户看到的是那句面向仓库维护者的提示：

```
ERROR console: 面板调用失败 world:soft-voice/controls.devices
  { error: 'Error: 请先运行仓库 scripts/install_world.py 配置独立语音环境' }
```

同一台机器改用 `install.cmd` 时，`select_integrated_name()` 在核显列表为空时直接抛错，而报错只打印核显列表，于是显示 `Available: []`——看起来像"一块显卡都没找到"，实际 GTX 1660 已被正确枚举。

也就是说：**Intel F 后缀 CPU、BIOS 关闭核显、以及其它无核显的台式机，两条安装路径都走不通**，而且提示都在把用户往错误方向带。这不是性能问题，是功能性缺陷。

已修复：安装器在绑定前先枚举显卡，列出全部设备并要求用户确认（`install.cmd` 交互式按回车即可），非交互运行时给出可复制粘贴的 `-DeviceName` 命令；应用内一键部署区分"没有核显"和"多个核显"两种情况，并明确说明"模型已下载，选好设备后再点一次部署"。独显仍然只能由用户显式指定，不做自动回退。

报告里"未接入显示 4 GiB、接入后显示 2.75 GiB"的判断是正确的：前者是未配置时的兜底值，后者才对应本机渐进 FP32 KV 布局，两个数字都与源码常量一一对应，不是随机抖动。

## 二、报告中最吓人的数字不是稳态性能问题

`deployment-check.json` 的首段 16 字耗时 19391 ms、RTF 5.77 确实扎眼，但把同一份 `installation.log` 里的分阶段日志摊开看，问题只出现在**第一次合成**：

| 阶段 | 首段（16 字，3.36 s 音频） | 第二段（19 字，3.44 s 音频） |
|---|---:|---:|
| Prefill | 3642 ms | 112 ms |
| CodecDecode | 13973 ms | 246 ms |
| TalkerDecode | 388 ms（42 帧） | 335 ms（43 帧） |
| CodePredictor | 1372 ms | 824 ms |
| 合计 | **19388 ms（RTF 5.77）** | **1525 ms（RTF 0.443）** |

多出来的约 17.9 秒集中在 Prefill 与 CodecDecode，正是 Vulkan 管线/着色器首次编译的特征：权重加载本身很快（1316 ms），编译被推迟到第一次真正提交计算时。

本机（AMD 核显 + NVIDIA RTX 4050 Laptop）的历史日志复现了同一现象，并证明了它是**一次性**开销：

| 本机日志（同一批着色器） | 首次合成 |
|---|---:|
| `baseline-nvidia.log`（机器上第一次跑该着色器集） | 25608 ms，RTF 8.003 |
| `adaptive-nvidia.log`（另一个进程，同一着色器集，驱动磁盘缓存已生效） | 1263 ms，RTF 0.395 |

所以驱动层的着色器磁盘缓存接住之后，新进程的首次合成并不慢。这一点也解释了 Issue #15 的自动诊断为什么看起来一切正常：它抓的是运行了一段时间的 worker，`realTimeFactor 0.493`、`firstChunkMs 681`、无欠载；分阶段日志里 TalkerDecode 稳定在 8.2 ms/帧、CodePredictor 19.2 ms/帧。

**结论：GTX 1660 的稳态性能健康，报告里 19.4 秒是首次运行的一次性编译成本，不是每句话的延迟，也不是"独显比核显慢"。** 本轮没有为此改动推理代码，也没有降低任何内存保护线。

界面已就地说明这一点：一键部署的测试阶段现在会提示"首次运行需要编译显卡着色器，独显上可能多等 20–30 秒，之后不再需要"，避免用户把等待当成卡死。

## 三、仍需用户确认的一点

驱动磁盘缓存是否在**每次重启桌宠**后都有效，本机只验证了"进程与进程之间"（同一次开机）。请报告用户在重启电脑后朗读第一句，确认首次合成是否仍然很快：

- 如果很快：一次性开销判定成立，无需进一步优化。
- 如果每次重启都慢：说明该驱动/系统的着色器缓存没有保留，届时应考虑在加载阶段显式预热管线，把等待挪到"正在加载"这一步并如实显示。

## 四、附带发现：一键部署的运行时版本落后于发布页

`world/src/deployment-manifest.js` 固定指向 0.5.3，与 `portable-release.json` 的 0.5.4（以及本次 0.5.5）不一致。该清单要求两个镜像提供**逐字节相同**的包，因此魔搭镜像必须同步上传新版本才能一起前进。本次把它对齐到 0.5.5，并在镜像尚未同步时只保留 GitHub 源，避免应用内装到比手动安装更旧的运行时。

## 五、本轮验证范围

- 设备选择：6 项单元测试覆盖"唯一核显自动选择、纯独显必须显式指定、多个核显要求选择、无显卡指向驱动、清单列出全部显卡"。
- 安装器：在真实便携包上跑通"唯一核显自动继续"，并用纯独显夹具分别验证非交互报错（给出可直接复制的命令）与交互选择（打印 `Selected device:` 后继续）。
- 界面：`deviceChoice` 的三种分支由 Node 测试覆盖；World 客户端新增 `console-0.4.9.js`，设备待选时主按钮改为"使用所选设备继续部署"。
- 未做：本机 Intel/GTX 1660 实机验收（无对应硬件）、真人听感、长时间连续朗读压力测试。用户报告中的 `subjectiveVoiceQualityApproved=false` 仍然成立。
