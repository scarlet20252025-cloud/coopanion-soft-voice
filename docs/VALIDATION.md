# 验证与已知问题

## 2026-10-11 原运行链路

保留的是已确认的 soft-child-design-2 参考音频。新句子由 0.6B Base 克隆生成，不是将原 WAV 变速播放。参考的原始设计由 Qwen3-TTS 1.7B VoiceDesign 生成；部署时不需要设计模型。

|项目|结果|
|---|---|
|生成 8 帧首块，离线三短句|约 0.48～0.50 秒|
|实际请求进入播放|约 0.69～0.86 秒|
|实际音频设备首次回调|约 0.72～0.88 秒|
|短句播放缓冲不足 / 设备 underflow|均为 0|
|三条音频自动转写|内容相符，标点和数字格式有差异|
|参考音频校验|与用户确认文件一致|

原始指标见 `evidence/2026-10-11-live-metrics.json`。上述结果针对原安装链路，不把打包后的静态检查等同于全新机器部署测试。移植后的验证结果见同目录后续记录。

## 独立项目验证

2026-10-11 在新的 Python 3.10 虚拟环境中安装固定依赖及项目包，复用校验过的同版本模型文件；用插件副本执行真实安装补丁与 Node → Python worker → GPU 合成 → 静音音频设备播放全链路。没有改动用户正在使用的插件文件。

- `doctor` 检查 GPU、音频输出及模型文件通过。
- 5 项无需 GPU 的测试通过，覆盖音频校验、模型缺失拒绝、源码解析、不兼容插件拒绝以及安装/回滚还原。
- 独立插件的短句首块 **773ms**，收到文本至进入播放 **781ms**，首次设备回调 **814ms**；缓冲不足与设备 underflow 均为 0。详情见 `evidence/portable-smoke.json`。静音测试验证播放链路，不代表主观音色再次验收。
- wheel 与源码包构建成功。当地 pip 构建隔离环境遇到 TLS 连接故障，使用 uv 安装相同固定构建依赖后以 `python -m build --no-isolation` 完成；没有关闭证书校验。
- 这不是在另一台全新电脑上的安装验证；外部模型网络下载、其他声卡及显卡仍可能存在环境差异。

## 不能据此保证的事情

- 没有证明任何文本都能保持完全相同的音色。用户报告过一次变声，换新对话后又恢复；没有保留下来的异常音频，所以根因未定。
- 前文完整解码与分块解码仍有浮点/边界差异。现在保留完整 codec 历史，以减少截断上下文带来的变化。
- 没有声纹异常自动拦截或自动重试，不会用“ASR 正确”冒充“音色正确”。
- 没有下一句并行预合成。当前排队时间包含前一句的播放时间。
- 没有 CPU、AMD、macOS 或所有 NVIDIA 型号验证。

优先保持当前音色与参数。后续性能优化应保存异常文本与音频、比较同句的整句/流式输出，再决定是否改变生成参数；不要仅凭听感报告就切换模型或静默回退到高延迟模式。
