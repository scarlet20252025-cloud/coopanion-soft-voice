# 0.5.2 长句修复与显存优化对照

作者 Asryto · 2026-10-15 · RTX 4050 Laptop GPU，Vulkan，Qwen3-TTS 0.6B Q8，固定 full-ICL 音色与种子。不是其他硬件的保证。

之前约 1 GiB 的优化已经应用：渐进 FP32 KV、单活动计算图、按需文本嵌入以及独显本地显存策略均保留。本次没有撤销这些优化。

## 同一组真实推理

关闭重复音频缓存；按实际 32 字分段路径合成，包含短句、中英混合长句、纯中文长句、故障后的短句。每 100 ms 采样本进程内存及 Windows GPU 计数器，音频保存并计算原始 PCM SHA256。首次测试和后续测试文件缓存不同，加载时间不能用来宣称冷启动提速。未进行真人听感验收。

| 指标 | 0.5.1 | 修复候选 0.5.2 |
|---|---:|---:|
| 专用显存采样峰值 | 1101.8 MiB | 1044.9 MiB |
| GPU 共享内存采样峰值 | 96.3 MiB | 96.3 MiB |
| 进程物理驻留峰值（系统计数） | 1089.4 MiB | 1088.6 MiB |
| 私有提交采样峰值 | 1715.3 MiB | 1733.9 MiB |
| 99 字混合长句 | 9.78 秒后失败，未完成 | 5.79 秒生成全部 19.76 秒音频 |
| 53 字纯中文生成 | 3.079 秒 | 3.054 秒 |
| 后续短句首块 | 195 ms | 198 ms |

旧版混合分段以逗号结尾，生成到 360 帧上限仍不结束，导致 KV 扩容；新版仅规范含拉丁字母分段的结尾标点。显存差额约 56.9 MiB 来自避免这次异常扩容，不是正常短句再省 56.9 MiB，也不能把未完成任务的时间与完成任务算成提速百分比。

纯中文及批准短句的 PCM 与旧版逐字节一致。正常短句显存原本已经约 1045 MiB。真实首块延迟并不等于扬声器首次出声时间。

## 两个未采用的底层实验

使用真实重新编译的 DLL，独立进程测试，不修改用户安装或默认设备。补丁保存在 evidence 中，不进入默认构建链路。

| 实验 | 专用显存峰值 | 物理驻留峰值 | 结果 |
|---|---:|---:|---|
| 输入预填充后释放 scheduler 临时缓冲 | 1042.0 MiB | 1089.0 MiB | PCM 一致；仅省约 2.9 MiB，不值得增加每段重建开销 |
| Talker FP16 KV，预测器仍 FP32 | 1016.4 MiB | 1089.1 MiB | 省约 28.6 MiB；批准短句从 3.20 秒变为 3.44 秒，PCM 改变；未采用 |

FP16 的私有提交采样峰值为 1597.7 MiB，但实际物理驻留没有下降；私有提交不能当成物理 RAM 节省。以上是单轮探索，不能推出普遍性能结论。FP16 未证明保留原有声音，不能仅因显存低于 1 GiB 就发布为默认方案。

## 修复及内存保护

生成达到上限时，只终止失败的当前段并停止其播放，不自动重播已经听到的内容；后续排队消息继续。页面保留“最近一次朗读异常”，避免把跳过当作完整读完。其他故障仍阻止后续合成，防止隐藏设备错误。

本轮没有可靠的物理 RAM 降幅，故已验证 NVIDIA 路径仍需 2.75 GiB 可用系统内存、自动恢复 3.25 GiB；核显仍为 3 / 3.5 GiB。显存与 RAM 分别评估，不通过降低阈值伪造优化。

后续优先研究计算图缓冲共享与无需降低精度的中间张量生命周期；必须覆盖多次合成、休眠唤醒、长句及真实播放，并在同一设备对照。进一步降低权重或缓存精度需要独立听感验收。
