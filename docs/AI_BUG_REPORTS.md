# AI 排错与自动提交 Issue

作者 Asryto 接收本扩展的问题，唯一反馈仓库为 [coopanion-soft-voice Issues](https://github.com/scarlet20252025-cloud/coopanion-soft-voice/issues)。本规则面向正在帮用户部署或排错的 AI；扩展默认只在本地留存报告；用户明确开启“自动提交脱敏 Issue”后，才会向本仓库提交必要的设备/性能摘要与阶段日志，不上传聊天、完整配置或音频。

当前用户已明确允许公开报障，且 AI 的 GitHub 工具/凭据可用时，确认问题后**自动提交 Issue**，不要只在本地修复而丢失反馈。该授权须来自当前用户或其明确委托的报障流程，仓库作者的说明不代替其他用户的授权。当前会话明确禁止上传时，以该限制为准。

1. 先读 README、安装教程与当前版本，确认问题属于本扩展。
2. 用版本、错误码和关键词检索开放及已关闭 Issue；相同问题补充到原 Issue，不重复创建。
3. 按 [诊断教程](DIAGNOSTICS.md) 运行采集脚本，必要时监测说话期间的 60 秒。区分复现结果、用户提供的读数和推测。附最小复现、机器与驱动、播放策略、实际设备/显存分配、加载/首次出声/RTF/断流指标；不能只说“运行正常”。
4. 删除密钥、令牌、邮箱、Windows 用户名、本地绝对路径、聊天原文及个人配置。只提交与问题有关的诊断摘要；不上传模型、参考音频或整个日志目录。
5. 使用 GitHub 工具的结构化参数，或 `gh issue create --body-file`；不拼接未经转义的 shell 文本。也可用 `scripts/report_issue.py --diagnostics 报告.zip --analysis 分析.md --submit`。Issue 包含必要脱敏诊断与相关日志；原始 ZIP 无法经 REST 附加时，把完整包交回用户。不只有分析而缺少证据。
6. 未登录、无法联网或工具权限不允许自主提交时，不要求用户反复配环境。默认运行 `report_issue.py` 生成 `*-for-author.zip`，包含诊断、性能日志、分析、Issue 草稿和未提交原因；把文件交给用户转给作者 Asryto。不能假装提交成功。
7. 修复用关联分支/PR。测试通过并满足验收要求后提交版本；确认 Release 和验收结果发布后再关闭 Issue，说明验证设备及尚未实测的硬件。用户要求暂停发布时保留本地修改，不擅自推送。
