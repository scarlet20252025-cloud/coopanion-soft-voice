## P0：Intel UHD 反馈，待实机日志

- [ ] 获取冷/暖启动的分阶段日志、实际 GPU/驱动、内存类型、RAM/显存、系统 GPU 负载及连续性读数；原报告 7.28 秒音频约 27.7 秒合成，不能宣称提速已解决。
- [ ] 验证完整缓冲是否消除合成欠载，并单独报告新增首声等待。
- [ ] 排查 CodePredictor 约 148 ms/帧与 Talker 约 59 ms/帧；区分内核执行、传输、CPU 调度与驱动，不提前归因为硬件不足。
- [ ] 纠正线程实验：现有原生入口固定 4 线程，外部 4→16 环境变量对照未证明真正改变线程数。需要记录生效值再测试。
- [ ] 报告机器的 RTX 5060 单独验证；不能套用 4050 的通过结果。保留 Intel 问题 Issue，待实机验证再关闭。

## P1：多设备自适应，待实现/验证

- [ ] 其他 NVIDIA 型号、AMD 独显、Intel Arc/iGPU 的设备及驱动组合实测表，包含失败样本。
- [ ] 用独立进程对显存分配路径做短 A/B，原始 PCM/参考/采样保持不变；按首声、RTF、断流、峰值内存选策略，失败回退。
- [ ] 策略缓存绑定实际设备、驱动及原生 DLL 哈希；驱动/引擎变更失效。当前只按 NVIDIA 厂商识别应用配置，尚无自动 A/B。
- [ ] 多句/长回复、休眠唤醒、游戏后台负载验证；单句最快结果不代替稳定性验收。

## P2：能效与内存，待验证

- [x] 本机 NVIDIA/AMD 渐进 FP32 KV 分配与真实 GPU 边界复制测试，保留原版 PCM；专用/共享内存分别记账。见 `VRAM_OPTIMIZATION.md`，其他型号和游戏并行仍待验证。

- [ ] 测量空闲基线、合成阶段功率和耗时，报告每秒音频能耗与唤醒成本。系统 GPU 总功率不能直接当成 TTS 功率，也不能只用吞吐推断省电。
- [ ] 比较常驻、保留 worker 休眠、完全退出的空闲占用、能耗、首声与抖动；按用户可选低功耗模式保留取舍。
- [ ] 复用推理临时缓冲、减少跨阶段复制/同步，检查 CodePredictor 调度与图提交；每次改动保留峰值内存和波形对照。
- [ ] 实验 FP16 KV 缓存：仅缓存部分理论减半，不能宣称整个模型减半；需 GPU 兼容性、长句音色和内存实测。
- [ ] 实测后才调整加载/恢复保护线，不为通过安装而降低门槛，不自动关闭游戏，不修改桌宠本体。

每项记录设备、驱动、版本、冷/暖状态、真实指标、证据与限制；失败也保存。明显性能回退时不作为默认策略发布。
