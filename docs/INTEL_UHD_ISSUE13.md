# Intel UHD 性能调查：Issue #13

作者 Asryto · 2026-10-15。状态：**尚未解决 Intel 慢速；未发布优化版，未改变默认后端或内存保护线。**

来源：[Issue #13](https://github.com/scarlet20252025-cloud/coopanion-soft-voice/issues/13)。运行时报告 0.5.3 / World 0.4.8，i7-13650HX，Intel UHD 驱动 32.0.101.7082，实际 Vulkan 设备为 Intel RaptorLake-S Mobile Graphics Controller。机器另有 RTX 5060，不自动切换。

## 已确认的瓶颈

历史日志含更快的记录，无法确认属于同一设备/运行，不能混算。最后七个完整阶段的音频合计 31.92 秒，native 耗时 102857.6 ms，与 recentPlayback 的 102873 ms 匹配。

| 阶段 | 七段合计 | 占原生总耗时 |
|---|---:|---:|
| CodePredictor | 58.466 秒 | 56.8% |
| TalkerDecode | 23.318 秒 | 22.7% |
| CodecDecode | 16.217 秒 | 15.8% |
| Prefill | 4.738 秒 | 4.6% |

整段缓冲使设备首次回调等到 102.886 秒。欠载为零，只证明之后播放连续，不能证明出声及时。分段提前播放会在 RTF 3.223 的设备上产生段间等待，不能伪装成吞吐优化，当前未改变用户的连续播放策略。

此样本进程私有提交约 1338 MiB、驻留约 1947 MiB、共享 GPU 内存约 985 MiB；共享内存不能再与系统 RAM 简单相加。不是启动峰值对照，不能据此降低 3 GiB 启动保护线。

## 实际实验及未采用原因

沿用原 DLL `02fe1d4e2aeb5502e399bb7f01b57748091bfc9eb5e436c436245d913407e1c1`、模型、固定音色和采样参数。现有预测器已将每帧十五步展开为一个缓存计算图；没有十五次主机 logits 回读可以直接消除。

本机 AMD Radeon 核显进行独立进程 A/B/C/A，关闭重复音频缓存，第一句只用于暖机，后两句按总音频秒数加权计算 RTF。生成 WAV，**没有进行设备播放或真人听感验收**。系统后台负载未锁定，只有一组正式对照，不是统计性能结论。

| 配置 | 暖态 RTF（越低越快） | 与前后基线的 PCM 对照 | 判断 |
|---|---:|---|---|
| 原版基线 A | 0.6801 | 与末次基线一致 | 对照 |
| Vulkan 每批节点上限 100 → 1000 | 0.6732 | 一致 | 比前后基线均值慢约 0.4%，没有收益 |
| 强制 MMVQ 量化矩阵向量内核 | 0.6469 | 不一致 | 不能认定保音色提速，不采用 |
| 原版回归 A | 0.6607 | 与首次基线一致 | 背景波动约 2.9% |

提交上限实验的共享显存仍为 969.562 MiB，私有提交约 1439 MiB；没有可支持降低启动要求的内存收益。首次探索还观察到原版同一句重复生成 PCM 不一致，正式对照逐位置比较两次基线，不能对整个平台宣称确定性。

本机不是反馈的 Intel UHD，以上结果不能证明 Intel 上这些策略无效或有效。精简后的数值证据见 `evidence/2026-10-15-intel-issue13/comparison.json`。

## 在反馈机器运行，不改安装配置

普通用户优先使用 [双击诊断工具](INTEL_DIAGNOSTIC_KIT.md)，自动识别目录、选择 Intel 核显、显示进度并生成脱敏 ZIP。下面命令仅保留给开发者。

下载包含此脚本的仓库源码，使用已经部署的运行时里的 `python/python.exe`，无需另下载模型。先让语音空闲，在扩展中暂时关闭语音以免两份模型同时驻留；记录原设备和开关，测试后自行恢复。不要关闭其它用户程序来强行凑内存。仍执行原有启动保护。

在 PowerShell 中，将下面三个路径替换成实际位置：

```powershell
& 'D:\轻核语音\python\python.exe' 'D:\源码\scripts\benchmark_intel_issue13.py' --runtime 'D:\轻核语音' --device 'Intel(R) RaptorLake-S Mobile Graphics Controller' --output 'D:\语音对照报告-01'
```

`--runtime` 是包含 `native-runtime.json` 的目录。设备名必须来自扩展实际检测，不猜名称；输出目录必须不存在，避免覆盖旧报告。脚本依次进行基线、提交批量、MMVQ、基线，每项最多 15 分钟；会显示当前项，失败停止并保留已完成结果。可用 `--variants submit-1000` 只测提交实验。

脚本只在子进程传入实验环境变量，显式选择指定 GPU；不更新文件、不切换桌宠设备、不上传数据、不降低保护线。第一句不是可靠冷启动测量。`firstChunkMs` 是模型回调，**不是扬声器出声**。结果始终标记 `acceptedForRelease=false`。

需要回传：`comparison.json`，失败时对应 `.log`；完整 `report.json` 和 WAV 保留本地辅助比对。日志可能包含本机路径，提交前脱敏，勿上传个人配置或聊天内容。附上测试时是否游戏/录屏、供电模式，以及测试前后的设备设置。用户授权后可将脱敏结果补充至 Issue #13；本工具不会自动公开资料。

## 下一轮验收

先取得同型号 Intel 的 A/B/A，再决定是否值得做其专用提交策略或内核优化。任何候选必须覆盖长句、真实首声、断流、取消及休眠恢复，验证音色且保留 NVIDIA 回归结果。未通过不替换稳定版，不关闭 Issue #13。不能将背景波动、不同长度音频或缓冲策略变化包装成算法提速。
