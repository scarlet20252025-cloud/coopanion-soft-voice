# 参考音色特征缓存与内存验证

## 0.4.5：自适应流式启动算法

这轮优化的是音频生产/播放调度，不是模型蒸馏，也没有减少神经网络计算量或改变采样参数。

原生回调按逐步增大的音频块返回。以前必须积累 1.2 秒音频才播放；现在观察至少三个回调的生成速率和最大间隔，排除一次性的前缀计算时间，用 0.32–1.2 秒的动态安全缓冲。快速稳定时可在第三块、约 0.56 秒音频处启动；间隔较大时保持更大缓冲。若真实播放发生断流或设备欠载，该 worker 后续自动使用固定 1.2 秒策略。

音频设备改为在进入原生推理之前打开。原生生产回调只入队音频，不再在计算线程中创建声卡流。初始无数据期间输出静音，不计作已开始播放后的断流；首次实际音频之后的欠载仍计数。短尾音入队前不会被完成标记提前截断。

同引擎顺序对照（固定短句、动态短句、固定长句、动态长句）：长句首次设备回调 836 → 455 ms，两者 PCM SHA256 完全一致，零断流、零设备欠载。短句 1371/917 ms，但固定短句包含首次建图，不能把全部差值归因于调度；动态短句检测到较大间隔后仍保留了 1.2 秒音频。更早候选存在输出差异，未部署；将声卡初始化移出原生回调后，最终短/长句对照均逐字节一致。设备初始化影响输出差异的具体底层机制没有单独证明。

复现：`python scripts/benchmark_buffer.py --runtime <Runtime> --output result.json`（实际播放四句）。证据在 `evidence/2026-10-14-adaptive-buffer/`。没有据此承诺游戏高负载下零断流，休眠后的模型加载时间仍然存在。

## 0.4.4 / World 0.3.0：低占用休眠与内存保护

扩展配置新增“低占用休眠”开关和“内存保护阈值（MiB）”。开启低占用休眠时保留 Python、播放器与驱动进程状态，但关闭原生模型上下文，释放权重、KV 和计算图；下一句通过同一 worker 重新加载模型。不是暂停进程或强制清工作集。关闭此开关则沿用完全退出 worker 的深度休眠。

实测第一次休眠合计提交内存 576 MiB，实际合成后再休眠 593 MiB；两次唤醒至首次设备回调 2551/2647 ms，均零断流和设备欠载。另一轮约 3041 ms，因此不能保证低占用休眠总比深度休眠快。深度休眠释放更彻底；低占用休眠仍需数百 MiB 保留驱动和库状态。数字是测试相关进程的提交内存，不等于物理驻留量或整机显存。

自动休眠时间与内存保护分别可关闭（设为 0）。保护阈值只在空闲且无排队时触发，不中断说话；建议 1536 MiB。唤醒仍需至少 4 GiB 空闲，内存不足继续走文字/恢复流程，不能通过降低休眠阈值绕过加载保护。休眠后不会因空闲内存恢复而无意义地来回加载，只有新语音或手动恢复才唤醒。

本机配置为 300 秒、低占用模式、1536 MiB；仓库默认仍关闭自动触发，安装者可按机器设置。升级需同时安装 Python 0.4.4 与 World 0.3.0。复验脚本末尾加 `light`，会执行两轮休眠/唤醒并播放两句，证据在 `evidence/2026-10-14-light-sleep/`。

## 0.4.3：启动加速

原分段测量中，资源校验约 1383 ms、原生模型初始化约 1720 ms；随后还合成一句被丢弃的预热语音，且播放器模块在 ready 消息后才导入，导致旧图表遗漏部分等待。

本次改动：

- 未变化的模型使用本机校验记录，比较绝对路径、设备/文件标识、大小、mtime/ctime 纳秒值和预期 SHA256；首次、记录损坏或任一项变化时重新全文校验。DLL 始终全文校验，`doctor` 也始终完整校验。记录仅作为可信本机环境的启动加速，不是防止恶意篡改文件与记录的安全边界。
- 原生后端不再生成丢弃的预热句，让第一句真实内容创建计算图。三次短/长/短句 PCM 与原版逐字节相同；其他后端仍保留原有预热。
- 播放器模块导入与模型初始化并行，二者完成后才报告 ready，使加载耗时和首句计时更准确。

同机实测：原完整 worker 就绪 4919 ms，本次 2176 ms；本次空闲唤醒到首次设备回调 3022 ms，断流与设备欠载为 0。旧实测首句约 5–6 秒且旧 totalStartMs 漏计导入时间，不直接用旧图表数值计算精确改善百分比。首次无校验记录、操作系统文件缓存未命中、后台负载高时可能更慢，不承诺每次 2 秒。

复现无预热 PCM：给 `scripts/benchmark_reference_memory.py` 添加 `--no-prewarm`；端到端加载/卸载/出声仍用 `scripts/verify_idle_unload.mjs`。证据在 `evidence/2026-10-14-startup/`。正在使用的 World 设置及音量不变。

## World 0.2.1：可选的空闲卸载

“配置 → 空闲卸载（秒）”设为 300，可在五分钟没有语音任务后退出模型 worker；0（默认）保持常驻。只在就绪、无排队、无播放及无初始化时卸载，不打断正在说的话。下一次成功的 pet_say 自动重新加载并朗读；静音和明确停用不会被自动解除。切回 0 时恢复常驻。

实测卸载后原 worker 及其子进程均不存在，不是强制清空工作集。唤醒后的首句约需 5–6 秒，播放中断流及设备欠载均为 0；完整唤醒加 3.52 秒音频播放耗时 9.41 秒。记录在 `evidence/2026-10-14-idle-unload/live.json`。连续聊天仍复用已加载模型。内存不足时遵守原有 4 GiB 启动门槛，转为文字，不强行加载。

缓冲审查：固定版本上游 `weight-ctx.h` 在权重上传后已清空 pending/staging；持久的计算图、KV、声码器状态供后续合成复用。本次没有未经验证地释放这些资源，也没有额外宣称常驻内存下降。

可用 `node scripts/verify_idle_unload.mjs <runtime-profile.json> <output.json>` 复验；脚本使用独立 World 配置，会播放一句话，结束后停止测试 worker，不修改桌宠的配置。

2026-10-14 在原有 Q8、核显 Vulkan、1024 KV 上继续优化，不改变模型、采样参数、参考音源或语速。

## 已采用：参考特征缓存

按照 [qwentts.cpp 官方 pre-encoded reference 方案](https://github.com/ServeurpersoCom/qwentts.cpp#quick-start)，保存参考 WAV 提取出的说话人 embedding 和 RVQ codes。以后启动直接使用这些数值，不加载只为分析参考音频服务的 speaker encoder、codec encoder 和相关临时计算缓冲。

缓存存于 Runtime 的 `reference-cache/`，按引擎 DLL 校验值、模型路径、codec 路径和音源 SHA256 隔离。模型与 codec 仍在加载前验证固定 SHA256。缓存采用有大小、维度、数值边界和摘要校验的 JSON，不使用 pickle。损坏、缺失时从原 WAV 重建，不切换音色。Python 持有的特征数组不会交给原生 malloc/free 释放。

首次提取后重新创建原生上下文，释放分析用编码器。首次准备略慢；之后缓存命中更快。缓存无法写入时仍可正常使用，但下次需重新提取。ZIP 导入流程不变，新的参考 WAV 自动获得独立缓存。

## 实测

独立进程、同一设备与模型、相同预热和三次短句/长句/短句。原始记录位于 `evidence/2026-10-14-reference-cache/`。

| 指标 | 原方案 | 缓存命中 |
|---|---:|---:|
| 预热后进程提交内存 | 2673.5 MiB | 2385.7 MiB |
| 三次合成后提交内存 | 2756.0 MiB | 2468.1 MiB |
| 初始化，不含预热 | 5.180 秒 | 3.379 秒 |
| 首段 PCM 回调 | 0.886 / 0.979 / 0.876 秒 | 1.001 / 0.870 / 0.896 秒 |
| 三次 PCM SHA256 对比 | 基准 | 全部逐字节相同 |

提交内存降低约 288 MiB（10.4%），不是降低 2 GiB。运行期间 Windows 明显裁剪工作集，因此不能把某次仅几百 MiB 的工作集读数当作完整物理内存需求。GPU 共享内存、文件页和整个桌宠其他进程也不等于这里的进程提交内存。保留 4 GiB 启动保护线；本轮未重新验证 CS2 共存。

首次生成缓存初始化 7.269 秒，三次合成后提交内存 2469.9 MiB，音频同样逐字节一致。

## 未采用的路线

- Flash Attention：同机实测 2471.2 MiB，未比特征缓存进一步节省；改变了生成样本与长度，故保留关闭。
- 更低权重量化：此前 Q4 未达到接受标准，本轮不把已认可声音换掉。
- 继续缩小 KV：1024 已有边界验证；进一步缩小会减少长参考音频和文本的上下文余量，不作为通用默认值。
- 强制清空工作集：只把页面赶出驻留内存，不减少已提交分配，还可能增加下一句延迟，不采用。
- 空闲卸载：能显著减少空闲占用，但下一句需重新加载与预热；当前保留控制台已有“立即停止 / 释放内存”，不暗中改变常驻行为。

## 复现

在两个独立进程中顺序运行（勿并行加载模型），缓存变体首次运行后再运行一次才能测命中。命令不会播放音频或修改桌宠配置。

```powershell
$env:PYTHONPATH = "$PWD/src"
.runtime-native/venv/Scripts/python.exe scripts/benchmark_reference_memory.py --runtime .runtime-native --variant baseline --output baseline.json
.runtime-native/venv/Scripts/python.exe scripts/benchmark_reference_memory.py --runtime .runtime-native --variant cached --output cache-first.json
.runtime-native/venv/Scripts/python.exe scripts/benchmark_reference_memory.py --runtime .runtime-native --variant cached --output cache-hit.json
```

回滚可恢复上一版 `native_engine.py` 并重启语音 worker；缓存文件不影响旧版本。不应删除模型或修改用户音色包。
