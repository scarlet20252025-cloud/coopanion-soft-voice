# CPU 与缓存试验（2026-10-12）

当前是隔离试验，未更改桌宠的语音设置，未替换已确认的声线。

## 最终诊断：拒绝当前 INT8 配置

用户明确拒绝 INT8 输出。进一步以本地 Whisper small 在 CPU 上复核：要求“我会乖乖等你”，INT8 被识别为“小刷我刚还我”；保持模型、参考、种子和文本不变的 FP32 对照被完整识别为“我会乖乖等你”，字符错误率 0、无削波。证据见 `2026-10-12-cpu-asr.json` 和 `2026-10-12-cpu-fp32-check.json`。本次逐 Linear 层动态 INT8 转换不能用于部署；这不是所有 INT8 实现都不可用的结论。

FP32 加载 7.391 秒，生成 22.730 秒，音频 1.600 秒，RTF 14.21。虽通过内容检查，仍未通过用户音色确认，且延迟不可用，未接入桌宠、未加入声音缓存。CPU 实验默认改成 FP32，INT8 只保留用于复现错误。所有新生成结果标为待审查隔离结果。

新增 `scripts/check_audio.py`：有限值、削波和 ASR 字符错误率检查。ASR 使用 CPU；错误率大于 20% 拒绝。检查通过只说明这些客观指标达标，不代表声线好听、身份一致或可发布；不自动播放、不自动缓存、不自动安装。测试覆盖本次错误输出、空输出、漏读和重复。它是独立检查工具，未修改生产 GPU 后端。

另核对了 https://github.com/predict-woo/qwen3-tts.cpp ，其参考声线接口采用 x-vector，不能直接视作当前完整 ICL 路线的等价替换，因此没有以它的宣传速度替代本机验证。当前没有通过验证的“免费、保留原声、不用 GPU、实时自由对话”方案。

## 清理内存后的重试结果

用户清理内存后完成了一次 CPU INT8 推理。启动检查空闲内存 7.23 GiB，模型加载与量化 13.662 秒，合成“我会乖乖等你。”耗时 42.412 秒，输出 7.12 秒，RTF 5.96。参考音频、完整 ICL、seed 44 保持不变。无 CUDA 推理，进程为 BelowNormal，2 线程。测试进程已退出，未接入桌宠。

这只是有限长度（max_new_tokens=90）的单次实验：没有测热启动重复生成，没有 ASR 检查，也未获用户音质确认，音频长度不能证明内容完整或发音正常。仅当前延迟已不适合实时对话，因此不继续占用资源做大量生成。证据：`evidence/2026-10-12-cpu-retry.json`。未通过的试验音频不随仓库分发；复现入口和指标见本页及 evidence。

修复了项目 `.venv/pyvenv.cfg` 中失效的解释器路径：实际目录为 `cpython-3.10.22-windows-x86_64-none`。旧配置备份为同目录的 `pyvenv.cfg.before-cpu-trial`。下文是首次尝试记录，其中的依赖和内存阻碍已在此次重试解决。

## 已验证的缓存播放

`coopanion_soft_voice.phrase_cache` 只查找完全匹配的文本，校验参考声线与音频文件的 SHA256，使用 Windows 播放 PCM WAV。没有匹配内容时直接返回，不调用模型，不把别的句子冒充回复。

本机 `.runtime/phrase-cache` 有三句现有音频。休息提示使用包内原始 `soft-child-design-2.wav`，另两句使用此前流式验证生成的音频。它们不是新合成或新音色。运行模块时指定 `--cache` 和完整文本；`--check-only` 仅检查缓存，不播放。缓存目录忽略提交，其他机器需要自行导入 WAV 和索引。

实测缓存读取并校验 1.880 ms；Windows 同步播放调用正常结束，约 4.713 秒（包含整段音频播放）。这不是首声延迟测量，也不是主观音质评估。没有导入 torch，没有模型推理。证据见 `evidence/2026-10-12-cache-trial.json`。

## CPU INT8 尚未通过验证

`scripts/cpu_trial.py` 是未完成推理验证的实验脚本：限制 2 个 CPU 线程、BelowNormal 优先级、禁用 CUDA、复用 0.6B Base 与完整 ICL 参考。仅尝试动态量化 talker 的 Linear 层，保留声码器和说话人编码器精度。不能据此宣称与原版声音相同或更快。

FP32 加载和量化转换的峰值内存比 INT8 成品高，因此设了保守的 7 GiB 空闲内存门槛；这不是已测得的内存需求。实测空闲内存 5.47 GiB，脚本在导入 torch、加载模型之前退出，未生成 CPU 音频。证据见 `evidence/2026-10-12-cpu-trial.json`。

本机项目 `.venv` 引用的旧插件 Python 路径失效，后续真正测试还需要修复运行时。此次缓存播放及 6 项测试使用独立 Python 完成。不要把这次结果当成 CPU 语音已经部署成功。

社区 C 引擎也作了调查：https://github.com/gabriele-mastrapasqua/qwen3-tts 。其 Windows 指引依赖 WSL2，本机没有可用 WSL 环境。为了单次实验未安装整套 Linux。上游同类 Ryzen 的指标不能代替本机测试。

后续须在内存充足、依赖修复后，验证量化兼容性、生成速度和可懂度，再由用户确认音色，才能考虑接入桌宠。当前缓存仅适用于固定提示，自由聊天仍没有通过验证的低负载语音方案。
